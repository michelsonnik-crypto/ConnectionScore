# ConnectionScore

מערכת מחקר והדגמה בעברית להערכת הסיכון לזמן מעבר בלתי מספיק בקונקשנים בטיסות פנים בארה״ב.

## מה נבנה בפועל

- הורדו **5,848,765 טיסות מקור** מעשרת חודשי BTS, ינואר–אוקטובר 2025.
- נבנו 2,263,127 זוגות מועמדים בדגימה מתועדת דרך ATL/ORD/DFW, עם תוויות 30/45/60 דקות וסטטוסים נפרדים לביטול/הסטה/חוסר.
- נרמול UTC, חצות ושעון קיץ; שתי ריצות מלאות הניבו ספירות וחתימות נתונים זהות.
- חלוקה כרונולוגית לאימון, ולידציה, כיול והדגמה; אפס טיסות משותפות בין החלקים.
- הושוו בסיס קבוע, בסיס לפי מרווח ורגרסיה לוגיסטית. מודלים הותאמו למדגם קבוע של 300,000 זוגות אימון תקינים.
- ממשק עברי עם השוואת מסלולים, תחזיות אמיתיות, תוצאות מחקר, כיול ומקורות.
- **TEST של נובמבר–דצמבר לא הורד, לא נקרא ולא שימש בהחלטות.**

## תוצאות ומגבלות

בוולידציה נבחרה לוגיסטית לתרחישי 30/45 דקות, ובסיס לפי מרווח לתרחיש 60. בהדגמה נמצאה הערכת חסר של הסיכון: בתרחיש 45 דקות ממוצע תחזית 7.07% מול 11.22% שנצפו. אין עדיין כיול מספק לשימוש תפעולי. בהשוואת מדיניות הבחירה לכלל המרווח הארוך רווח אי־הוודאות כולל אפס; לא הוכח יתרון.

המדד בודק האם יציאת ההמשך **המתוכננת** פחות הגעת הראשונה **בפועל לשער** מותירה פחות מהסף. הוא אינו מדידת עלייה/פספוס של נוסע או זמן מינימום רשמי. הזוגות נבנו מחקרית; אין אימות שנמכרו בכרטיס משותף. אין מחיר חי או חיזוי לתאריכים מחוץ לכיסוי. לוח BTS המדווח אינו snapshot של לו״ז ביום ההזמנה.

## צפייה במערכת

[אתר המחקר הפרטי](https://connectionscore-research.michelsonnik.chatgpt.site)

האתר מציג תחזיות מחושבות מראש ל־120 קבוצות חלופות היסטוריות מסוף אוקטובר. זהו ממשק סטטי של ניסוי אמיתי, לא מנוע הזמנות או שרת חיזוי לתאריך שרירותי.

לצפייה מקומית ללא הרצת המחקר מחדש:

```bash
python -m http.server 8000 --directory app
```

פתחו `http://localhost:8000`. קובץ `app/research.json` כבר כולל תחזיות אמיתיות ותוצאות. אין לפתוח `index.html` כקובץ ישיר, כי טעינת JSON דורשת HTTP.

## שחזור המחקר

Python 3.11 ומעלה, מסד אזורי IANA במערכת, חיבור אינטרנט וכמה GB פנויים לזיכרון/נתונים. נבדק על Linux עם Python 3.12. התקינו בסביבה וירטואלית:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/run_research.py
```

התהליך מוריד רק את חודשי הפיתוח, בונה זוגות, מאמן ומכייל, ומייצא נתוני ממשק. הוא **אינו ניגש ל־TEST**. לפירוט השלבים:

```bash
python scripts/fetch_data.py --research
python scripts/build_connections.py
python scripts/train_models.py
python -m unittest discover -s tests -v
node --check app/app.js
python scripts/verify_app.py
```

Node נדרש רק לבדיקת תחביר JavaScript, לא להרצת המחקר או שרת הממשק. הקוד והגרסאות נעולים; כל קובץ מקור מתועד ב־`data/manifest.json` עם URL, תאריך ו־SHA-256. המקור airportsdata נעול ל־commit. יש לשמור snapshot נתונים כדי להבטיח שחזור גם אם ספק משנה קובץ. קובצי המודל ב־`artifacts/` וקובצי נתונים גדולים אינם בענף הקוד.

תשעה מבחני מדע/זליגה עברו, וכן בדיקות עקביות הנתונים, מונוטוניות הספים ותחביר JS. בדיקת דפדפן חזותית ואינטראקטיבית לא בוצעה: כלי הדפדפן של הסביבה אינו זמין.

[חבילת הנתונים הראשונית — ינואר בלבד, כ־33 MB](https://github.com/michelsonnik-crypto/ConnectionScore/raw/refs/heads/data/2025-01/datasets/ConnectionScore-data-2025-01.zip) נשמרת בענף `data/2025-01`. היא קודמת להרחבה ואינה כוללת את יתר חודשי המחקר או את המודל; השתמשו בסקריפטים לשחזור הגרסה הנוכחית. להרחבת האחסון יש לבחור פתרון מתאים ולא לצבור קבצים גדולים ב־Git.

## עבודה בצוות והמשך אקדמי

בעל המאגר מוסיף חברים ב־Settings → Collaborators. לכל שינוי פותחים ענף ו־Pull Request עם בדיקות ותיעוד. לא מעלים סודות או מסמכי צוות אישיים.

הגרסה מספקת אב־טיפוס מחקרי עובד. היא אינה דוח גמר מוכן להגשה. נותרו אישור הגדרות פתוחות עם המנחה, סקירת 2–3 מאמרים, ניתוח רגישות מורחב, בחינת drift/כיול, נעילת מדד תועלת מעשי, ולאחר מכן פתיחת TEST מתועדת פעם אחת. אין לטעון שהוכחה תועלת לפני הערכה סופית.
